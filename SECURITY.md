# Security Policy for Venumity UI

</div>

## Which Versions Are Supported

Venumity UI does not currently use version‑specific security support. To stay protected, we strongly advise using the most recent release at all times.

## How to Report a Security Issue

Your safety matters to us. If you come across a security flaw in Venumity UI, please let us know as soon as possible.

**Where to send your report:**

- Drop us an email - [thevinayakgore@gmail.com](mailto:thevinayakgore@gmail.com)  
- Or send a direct message on X (Twitter) - [@thevinayakgore](https://twitter.com/thevinayakgore)

To help us investigate effectively, kindly include -

- Clear steps to reproduce the vulnerability  
- What impact it could have  
- Code extracts or screenshots that illustrate the issue  

**What happens after you report -**

- We’ll acknowledge receipt within 48 hours  
- You’ll receive ongoing updates about our progress  
- If the vulnerability is confirmed, we’ll agree on a timeline for public disclosure  
- We’ll publish a fix and an advisory (when applicable)  
- If the issue is deemed out of scope, we’ll explain why  

We value responsible disclosure and will happily acknowledge contributors who report valid security findings.

## Where Contributions Are Welcome

To maintain security and project stability, we only accept contributions in the following areas -

- **UI Components** – New components or improvements to existing ones  
- **Resources & Documentation** – Guides, tutorials, and other learning content  
- **CLI Tool** – Bug fixes and enhancements for the command‑line interface  

**We do NOT accept contributions for -**

- Core infrastructure or build system changes (unless previously discussed)  
- Registry API modifications without prior approval  
- Anything that could introduce security vulnerabilities (e.g., embedding external scripts, tampering with authentication logic)  

If you’re unsure whether your idea fits, feel free to open a discussion or issue first.
